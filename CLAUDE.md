# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Investment opportunity scanner for US stocks and bonds: ingest fundamentals/prices/yields, score securities against investment philosophies (Graham first), emit signals on score transitions, and (later) feed an in-app alert feed, a paper-trading sandbox and an optional Telegram channel. It is built in phases; **Phases 0-2 are done and Phase 3 (signals and alerts) is built except for the intraday fast loop**: scoring graph (Graham, Buffett, Lynch, Greenblatt and Fisher nodes plus Piotroski/Altman guardrails), data layer, ingestion, the point-in-time metrics layer, API, web scaffold. Not built yet: the Beneish guardrail, bond scorers, intraday price polling with incremental re-scoring (the worker only runs the Telegram bot, delivery retries and the single-instance lock), the paper-trading sandbox and the real UI. Not investment advice.

## Architecture

**Scoring graph (`packages/core/src/fin_core/graph/`).** A LangGraph `StateGraph` built in `build.py`: every node in `PHILOSOPHY_NODES` (`nodes/__init__.py`) runs in parallel from START, then `guardrails` -> `aggregate` -> `decide` -> END. Nodes write `philosophy_results` through a merge reducer (`state.py`), and each returns the same `ScoreResult` contract (`models.py`), so a deterministic node can later be swapped for an LLM-agent node (`impl: deterministic | llm` per node in `config/philosophies.yml`) without touching the wiring. To add a philosophy: new module in `graph/nodes/`, register it in `PHILOSOPHY_NODES`, add its thresholds and a weight to `config/philosophies.yml`. `decide` emits a signal only when conviction crosses a threshold relative to `previous_conviction` (buy >= 70, sell < 50 are constants in `build.py`), never on every run. A node may *abstain* (`ScoreResult.evaluated=False`, e.g. Buffett with under 5 years of history): `aggregate` leaves it out of the weighted mean instead of counting a 0 and names it in the explanation; if every node abstains the conviction is `None` (not 0.0) with no signal (`all_abstained`, also in the API response), so missing data can never look like a collapse and trigger a sell, and a stored 0.0 never masquerades as a previous view. The `guardrails` node (`graph/guardrails.py`) does not add to conviction: it computes a Piotroski F-score and an Altman Z'' (non-manufacturer variant, book values only) and *caps* conviction below the sell threshold (`guardrail_veto`, with `guardrail_reasons` in the explanation) when the F-score share (passes / evaluable signals) is at or below `veto_share_at_or_below`, or when Z'' is in the distress zone **unless** the company is visibly profitable and cash-generative (net income and operating cash flow both positive), because buyback-heavy companies show negative equity and look distressed (McDonald's, Starbucks); that case becomes a `guardrail_notes` entry, and missing cash-flow data keeps the veto; it abstains for sectors in `guardrails.skip_sectors` (Financials) and when too few signals have data, and signals without data are not counted against the company. Beneish is not built (needs receivables, SG&A, PP&E). Shared fiscal-year helpers (including `cagr`, a 3-year-smoothed growth rate) are in `graph/data.py`. Lynch (`nodes/lynch.py`) classifies by EPS growth (fast grower / stalwart / slow grower) and applies category-specific criteria, with a dividend-adjusted PEG; cyclicals and turnarounds *abstain* because a PEG is meaningless for them; asset plays are not modelled. Greenblatt (`nodes/greenblatt.py`) scores earnings yield and return on capital against **absolute thresholds per stock**, not the original cross-sectional ranking (that would need stored scores for the whole universe); it abstains for Financials/Utilities and multi-class issuers. Fisher (`nodes/fisher.py`) scores only the quantifiable subset of his 15 points (growth, margins and their trend, R&D intensity, dilution); missing R&D fails as "no data". All five philosophies have equal weights in `config/philosophies.yml`; the registry and the config sections/weights must stay in sync (tested). Buffett and Lynch (like Greenblatt and the guardrails) abstain for `skip_sectors` (Financials). Buffett (`nodes/buffett.py`) works from `SecurityMetrics.annual`: durable ROE, operating margins, positive earnings, debt payback, capex intensity, and a margin of safety on owner earnings (net income + D&A - capex, capitalised at a fixed discount rate; a deliberately simple earnings-power value, not a forecast, and strict: it needs market cap <= 7.5x owner earnings for a 25% margin, deducting total rather than maintenance capex); thresholds are in `config/philosophies.yml`. Graham deliberately fails non-positive P/E, P/B and negative debt/equity; the P/E x P/B product requires both factors positive.

**Data layer (`fin_core/db/`).** SQLAlchemy 2 models, repository functions, and Alembic migrations that live **inside the package** (`db/migrations/`, shipped in the wheel so non-editable images can migrate). Migrations are hand-written; a test asserts they match `models.py`, so every model change needs a new revision. Code must run on both Postgres (production) and SQLite (fast tests), hence the dialect switch in `repo._insert`. Key semantics:
- `fundamental_facts` keeps every filed version of a fact with its `filed` date; `repo.facts_as_of(as_of)` returns only what was public then (restatements invisible until filed). Instant facts store `period_start == period_end` so the natural key has no NULLs.
- `repo.upsert_securities` only updates columns a row provides (absent columns are left alone, so the universe sync never wipes a resolved CIK).
- TimescaleDB is optional: the migration turns `price_bars` into a hypertable only if the extension exists. The database must be UTF-8 (SQL_ASCII makes psycopg 3 return bytes and breaks SQLAlchemy).

**Metrics layer (`fin_core/metrics/`, `fin_core/scoring.py`).** Bridges storage and the graph: `compute_metrics(session, ticker, as_of)` builds a `SecurityMetrics` using only data public at `as_of` (facts by filing date via `facts_as_of`, latest price bar <= `as_of`). `annual.py` decides which facts count: 10-K family only, flow concepts need a ~1-year duration, stock concepts are balance-sheet instants, and when a concept is reported under several XBRL tags the highest-priority tag in `CONCEPT_TAGS` wins per fiscal year. Each ratio uses numerator and denominator from the same fiscal year (an older value never leaks into a newer ratio; a warning says when a ratio had to use an older year); the book value pairs equity with the share count on the same 10-K's cover. Missing data stays `None` and is explained in `metrics.warnings`, never silently filled, with two documented exceptions that also warn: missing debt is 0 only when that year's balance sheet exists, and no dividend data means 0 dividend years. Non-positive EPS/equity are kept as negative ratios so scorers can reject them explicitly. `signal_blockers` (a subset of the warnings: no or stale price, no or stale fundamentals) makes the graph's `decide` node withhold buy/sell signals while the score is still reported. Graham's P/E uses `pe_avg3` (3-year average EPS), falling back to latest-year EPS with a note. Multi-class issuers (`MULTI_CLASS_TICKERS`, e.g. BRK-B) get no book value/P/B, because EDGAR's company facts have no class dimension; `normalize_facts` drops same-key facts with conflicting values instead of letting one class overwrite another. `annual_series` also derives `TotalDebt`: the one definition of debt every consumer uses (the noncurrent tag plus the current portion, but never adding the current portion to the total tag, which already includes it), and keeps share counts from a single source per company (cover page before balance sheet) so year-over-year share changes never compare different kinds of count. `SecurityMetrics.annual` carries the fiscal-year history the multi-year scorers use. `score_security` = `compute_metrics` + graph; the API exposes it as `GET /api/securities/{ticker}/score`.

**Signals and alerts (`fin_core/signals/`, `fin_core/alerts/`, `fin_core/scoring_run.py`).** Scoring is a persisted state machine. `signals.engine.score_and_record` stores every run in `scores` (append-only, JSON details) and feeds the graph a `previous_conviction` taken from the last *actionable* stored score: conviction set AND not computed on blocked (stale/missing) data. A blocked run is stored but never becomes the baseline (otherwise the buy would be swallowed when fresh data arrives); a NULL-conviction run is not a baseline either, so the next real score is `emerging`, not `buy`. Re-running with unchanged data is idempotent. `alerts.policy` (`config/alerts.yml`) decides which signals become alerts: sells only for watchlist stocks, a 24h per-kind cooldown overridden by a >= 10 point conviction move. **Hysteresis**: after a buy/emerging signal another buy needs conviction to have fallen below 65 (`BUY_REARM_BELOW`) in between, after a sell another sell needs it back at >= 55 (`SELL_REARM_ABOVE`); derived from stored scores by `signals_repo.armed_state` (actionable scores only) and passed to `decide` as `buy_armed`/`sell_armed`, so a score flapping around 70 or 50 signals once. **Delivery** is channel-independent and crash-safe: creating an alert also writes its `alert_deliveries` rows in the same transaction (in_app `sent`; muted channel `skipped`; others `pending`), so a channel enabled later never replays old alerts (no rows exist for it). Sending (`pipeline.send_due`, aliased `retry_failed`) happens after commit, outside any DB transaction: each delivery is first claimed by an atomic compare-and-set on `attempts` (`claim_delivery`), so concurrent callers (scoring run and worker) cannot double-send; the outcome is recorded in its own short transaction. A failed delivery is retried with backoff (`retry_backoff_minutes`, `max_delivery_attempts`), a `pending` row left by a dead process is retried after `pending_timeout_minutes`, and a channel muted when a delivery falls due has it set to `skipped`. A channel exception never escapes (`ChannelError` text is recorded; any other exception by type only). Signals carry `processed_at`/`suppressed_reason`: `process_signals` decides per signal in its own transaction, and `run_scoring` also sweeps signals left unprocessed by an interrupted run (`pending_signal_ids`) without re-alerting deliberately suppressed ones. The in-app feed (`GET /api/alerts`) is always on. Telegram (`alerts/telegram.py`, plain httpx, command bot answering only the configured chat) exists only when `FEATURE_TELEGRAM_ENABLED` is on: off means no client, no token needed and zero calls; on without `TELEGRAM_BOT_TOKEN`/`TELEGRAM_CHAT_ID` fails at startup (`ChannelConfigError`). The bot token is in every request URL, so it is kept out of errors and logs. Bot polling is at-most-once: the update offset is persisted (`channel_state.update_cursor`) before each command runs, so a failing reply or a restart never replays `/mute` or `/unwatch`. `scoring_run.run_scoring` = score universe + alerts + delivery pass, tracked in `ingestion_runs` (source `scoring`; `partial` if any security or `signal <id>` failed, `failed` if every security failed). The worker (`fin_api.worker`) holds a Postgres advisory lock through `LeaderLock`, which re-verifies the lock every loop (`pg_locks`), re-acquires it after a lost connection and exits with status 3 if another instance took it (status 2 on invalid channel config). `scores` is append-only and not yet pruned; a retention policy is on the backlog.

**Providers and ingestion (`fin_core/providers/`, `fin_core/ingest.py`, `flows/fin_flows/ingestion.py`).** Providers sit behind small protocols (`providers/base.py`): `edgar.py` (ticker->CIK, XBRL company facts, mapped to normalized concepts via `edgar_concepts.py`), `fred.py` (yields/spreads), `yfinance_provider.py` (prices), `alphavantage.py` (fallback fundamentals). Provider errors must never contain credentials (API keys travel in query strings). `ingest.py` jobs write an `ingestion_runs` row: a run is `failed` until it completes normally, one bad ticker/series (including DB errors) makes it `partial`, `RateLimitError`/`AccessDeniedError` abort it, and stale `running` rows are failed by the next run. Prefect flows in `flows/` are thin wrappers that raise on a total failure. `fin_flows.pipeline.daily_pipeline_flow` chains sync-universe, prices, yields, fundamentals and scoring in one flow (a failing step does not stop the later ones; the flow fails at the end naming them), and is the only scheduled deployment (`fin_flows.serve`, weekdays 21:30 UTC); each step is also deployed without a schedule for manual runs. The always-on minute-level loop is meant to be a separate service, not a Prefect job.

**Config and flags.** `config/*.yml` is found by walking up parent directories from the module file (`load_config`, `load_universe`, `FeatureFlags`), which is why Docker images copy `config/` next to the venv. Feature flags come from `config/features.yml`, overridable by `FEATURE_<NAME>` env vars; `telegram_enabled` is off by default and, when it exists, must not start the bot or require a token while off.

**API and web.** `apps/api` (`fin_api.main`) exposes `/healthz` (liveness), `/readyz` (config/graph load plus a DB check when a DB is configured; 503 if unreachable), `/api/features`, `/api/score` (score caller-supplied metrics; responses include `guardrail_results`) and `/api/alerts` (feed with cursor and unread filter; `POST /api/alerts/{id}/read`), `/api/opportunities` (ignores scores older than `max_age_days`, default 10), `/api/watchlist` and `/api/channels` (database-backed; 503 without a database), and `/api/securities/{ticker}/score` (score a stored ticker; 404 unknown ticker, 422 future `as_of`, 503 without or with an unreachable database). `apps/web` is a Vite + React + TypeScript scaffold only.

**API auth.** State-changing endpoints (`PUT`/`DELETE /api/watchlist/{ticker}`, `POST /api/alerts/{id}/read`) require `Authorization: Bearer $API_TOKEN` (`require_write_token`, constant-time compare). Default-deny: with `API_TOKEN` unset they return 503; wrong or missing token is 401. Dev compose defaults it to `dev-token`, prod compose requires it. Read endpoints are open: keep the API behind the proxy's auth until the UI has a login.

**Deployment prep.** `deploy/` has one `python.Dockerfile` for all Python images (`--build-arg PACKAGE=fin-api|fin-flows`, must stay `uv sync --no-editable`), a web/nginx image, a dev compose file and a prod-shaped template. A one-shot `migrate` service runs before api/worker/flows. Nothing is deployed anywhere by this repo.

## Constraints and gotchas

- Prefect's server image tag in both compose files must equal the Prefect version locked in `uv.lock` (`flows/tests/test_versions.py` enforces this). `apps/api/pyproject.toml` caps FastAPI below 0.137 because the Prefect version in the shared env breaks on newer FastAPI; re-check both when upgrading Prefect.
- SQLite does not enforce column types/lengths (e.g. `accession` is VARCHAR(32)), so a change to models, repository code or DB-touching tests must also be run against Postgres (`TEST_DATABASE_URL`); that is how a too-long test accession was caught.
- Every `python -m <module>` in the compose files must name a real module (tested).
- Stored prices are the source's split/dividend-**adjusted** prices, not as-traded. If a refresh shows stored bars were restated, `ingest_prices` re-fetches the whole history. A point-in-time backtest of price-based valuation needs raw OHLC plus adjustment factors, which does not exist yet.
- The Telegram channel and bot were written from the Bot API docs and tested only against a mocked API (the sandbox cannot reach Telegram).
- The EDGAR and FRED providers were written from public API docs and tested only against synthetic fixtures (`packages/core/tests/fixtures`, made-up numbers). They have not been verified against the live APIs (a sandbox that blocks `sec.gov`/FRED cannot run them); the `-m live` tests are the check. The EDGAR 403 rate-limit-vs-bad-User-Agent split is an unverified heuristic. The facts for R&D, inventory, net PP&E and current debt (used by Lynch/Greenblatt/Fisher) only exist after fundamentals are re-ingested; until then those nodes abstain or report "no data". Every concept in `CONCEPT_TAGS` must also be classified in `metrics/annual.py` (stock/flow/snapshot), or it is silently dropped (a test enforces this).
- All thresholds in `config/philosophies.yml` are reasoned starting points, not calibrated; the planned backtester should tune them. First on the list: Buffett's margin of safety (very strict), then Fisher's R&D criterion, which lowers the score of companies that report no R&D (a deliberate choice, but it biases an equal-weighted composite).
- SEC requires `SEC_USER_AGENT` with contact details; FRED needs `FRED_API_KEY`. Copy `.env.example` to `.env` (never commit it).
