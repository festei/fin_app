# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Investment opportunity scanner for US stocks and bonds: ingest fundamentals/prices/yields, score securities against investment philosophies (Graham first), emit signals on score transitions, and feed an in-app alert feed, a paper-trading sandbox and an optional Telegram channel. It is built in phases; **Phases 0-5 are done (Phase 3 except for the intraday fast loop)**: scoring graph (Graham, Buffett, Lynch, Greenblatt and Fisher nodes plus Piotroski/Altman guardrails), data layer, ingestion, the point-in-time metrics layer, API, paper-trading sandbox, web UI. Not built yet: the Beneish guardrail, bond scorers, intraday price polling with incremental re-scoring (the worker only runs the Telegram bot, delivery retries and the single-instance lock), bond screens in the UI. Not investment advice.

Specs for each executed plan are in `docs/specs/` and end-to-end architecture diagrams (Mermaid) in `docs/architecture/`; update the matching diagram when a change alters a component.

## Architecture

**Hexagonal layout (`docs/architecture/10-hexagonal-architecture.md`, spec `docs/specs/009-hexagonal-redesign.md`).** The backend is a protected core with adapters around it. Dependency rule: `fin_domain <- fin_application <- adapters <- fin_bootstrap <- apps`; arrows only point inward, adapters never import each other, and apps (`fin_api`, `fin_worker`, `fin_flows`, `scripts/seed_demo.py`) reach adapters only through `fin_bootstrap.Container`.
- `fin_domain` (stdlib only, no clocks: `now`/`as_of` are parameters, tz-aware UTC only, money `Decimal`): bounded contexts `shared`, `market_data`, `scoring`, `signals`, `sandbox`, chained `sandbox > signals > scoring > market_data > shared` and referencing each other by `Ticker`, never by database id.
- `fin_application` (no third-party deps): use cases, DTOs and the **ports** (Protocols in `ports/`: `UnitOfWork` + repositories + read-side queries, provider sources, `AlertChannel`, `ChatBot`, `ScoringEngine`, config sources, `Clock`, `SingleInstanceGuard`). A use case is `with uow_factory() as uow:` (commit on clean exit, rollback on error).
- Adapters: `fin_persistence` (SQLAlchemy, Alembic, `SqlUnitOfWork`, `PgAdvisoryLeaderLock`; logs every `SQLAlchemyError`, then translates it (`storage_errors.py`): connection problems (`OperationalError`, `InterfaceError`; a deliberately broad bucket that also holds lock timeouts and deadlocks, which are retryable) into `StorageUnavailable` (the API answers 503; one WARNING line, no traceback, because an outage repeats it for every probe), any other database error (constraint, and on Postgres a missing table) into `StorageError` (500; ERROR with the full traceback; the message is the error's kind plus the driver's first line, never the SQL)), `fin_providers`, `fin_telegram`, `fin_langgraph`, `fin_config` (config discovery, `FeatureFlags`, universe). `fin_bootstrap` holds `Settings` (the process environment is read there, with two deliberate exceptions: `fin_config` reads `FIN_CONFIG_DIR`, `FEATURE_*` and `FEATURES_FILE`, and the vendor clients keep their own credential fallbacks; build per-purpose settings with `dataclasses.replace(Settings.from_environ(), ...)`, never `Settings(...)` from scratch) and the `Container`; `fin_testkit` has in-memory fakes of every port (tests only).
- Enforced, not conventional: the core packages declare no dependencies, `packages/domain/tests/test_core_isolation.py` checks metadata and imports, `uv run lint-imports` runs 8 import-linter contracts, ruff bans imports and naive clocks in the core. `packages/bootstrap/tests/test_repository_layout.py` checks that every package's tests are in `testpaths`.
- Where to add: a philosophy = pure function in `fin_domain/scoring/philosophies/` + registry + `config/philosophies.yml` weight + node in `fin_langgraph`; a provider = implement the source port in `fin_providers`, build it in the `Container`; a channel = implement `AlertChannel`, register in `fin_bootstrap/channels.py`; a use case = class in `fin_application`, tested on `fin_testkit` fakes, exposed as a `Container` property; a table = model + new Alembic revision + repository method + contract test (memory, SQLite, Postgres).
- Ports are tested by shared contract suites that run on the in-memory fake and on SQLite/Postgres (`uow_factory` fixture), so a fake cannot drift from the real adapter. Scorer tests live in `packages/bootstrap/tests/scoring` (they use the DB-backed helpers).

**Scoring (`fin_domain.scoring`, `fin_langgraph`, `fin_application.scoring`).** The rules are pure functions in the domain: the five philosophies (`scoring/philosophies/*.py`, each `(SecurityMetrics, thresholds) -> ScoreResult`, registered in `PHILOSOPHIES`), the guardrails (`guardrails.py`, `assess_guardrails`), the aggregation (`aggregate.py`) and a reference engine `assess()`. `fin_langgraph.LangGraphScoringEngine` implements the `ScoringEngine` port by running the same functions as a LangGraph `StateGraph` (every philosophy node in parallel from START, then `guardrails` -> `aggregate` -> END; state in `state.py`, nodes in `nodes.py`); a parity test holds it to `assess()`. Every philosophy returns the `ScoreResult` contract (`scoring/models.py`, plain dataclasses), so a deterministic scorer can later be swapped for an LLM-agent one (`impl: deterministic | llm` per philosophy in `config/philosophies.yml`; `run_philosophy` raises for `llm` until it exists). To add a philosophy: new module in `scoring/philosophies/`, register it in `PHILOSOPHIES`, add its thresholds and a weight to `config/philosophies.yml` (`validate_config` rejects a config that disagrees with the registry). Whether a conviction is a *signal* is not scoring: `fin_domain.signals.decide_signal` emits one only when conviction crosses a threshold relative to `previous_conviction` (buy >= 70, sell < 50, `BUY_THRESHOLD`/`SELL_THRESHOLD` in `signals/decider.py`), never on every run; a guardrail veto caps conviction at `VETO_CAP` (49), pinned below the sell threshold by a test. A node may *abstain* (`ScoreResult.evaluated=False`, e.g. Buffett with under 5 years of history): `aggregate` leaves it out of the weighted mean instead of counting a 0 and names it in the explanation; if every node abstains the conviction is `None` (not 0.0) with no signal (`all_abstained`, also in the API response), so missing data can never look like a collapse and trigger a sell, and a stored 0.0 never masquerades as a previous view. The `guardrails` node (`scoring/guardrails.py`) does not add to conviction: it computes a Piotroski F-score and an Altman Z'' (non-manufacturer variant, book values only) and *caps* conviction below the sell threshold (`guardrail_veto`, with `guardrail_reasons` in the explanation) when the F-score share (passes / evaluable signals) is at or below `veto_share_at_or_below`, or when Z'' is in the distress zone **unless** the company is visibly profitable and cash-generative (net income and operating cash flow both positive), because buyback-heavy companies show negative equity and look distressed (McDonald's, Starbucks); that case becomes a `guardrail_notes` entry, and missing cash-flow data keeps the veto; it abstains for sectors in `guardrails.skip_sectors` (Financials) and when too few signals have data, and signals without data are not counted against the company. Beneish is not built (needs receivables, SG&A, PP&E). Shared fiscal-year helpers (including `cagr`, a 3-year-smoothed growth rate) are in `scoring/series.py`. Lynch (`scoring/philosophies/lynch.py`) classifies by EPS growth (fast grower / stalwart / slow grower) and applies category-specific criteria, with a dividend-adjusted PEG; cyclicals and turnarounds *abstain* because a PEG is meaningless for them; asset plays are not modelled. Greenblatt (`scoring/philosophies/greenblatt.py`) scores earnings yield and return on capital against **absolute thresholds per stock**, not the original cross-sectional ranking (that would need stored scores for the whole universe); it abstains for Financials/Utilities and multi-class issuers. Fisher (`scoring/philosophies/fisher.py`) scores only the quantifiable subset of his 15 points (growth, margins and their trend, R&D intensity, dilution); missing R&D fails as "no data". All five philosophies have equal weights in `config/philosophies.yml`; the registry and the config sections/weights must stay in sync (tested). Buffett and Lynch (like Greenblatt and the guardrails) abstain for `skip_sectors` (Financials). Buffett (`scoring/philosophies/buffett.py`) works from `SecurityMetrics.annual`: durable ROE, operating margins, positive earnings, debt payback, capex intensity, and a margin of safety on owner earnings (net income + D&A - capex, capitalised at a fixed discount rate; a deliberately simple earnings-power value, not a forecast, and strict: it needs market cap <= 7.5x owner earnings for a 25% margin, deducting total rather than maintenance capex); thresholds are in `config/philosophies.yml`. Graham deliberately fails non-positive P/E, P/B and negative debt/equity; the P/E x P/B product requires both factors positive.

**Data layer (`fin_persistence`).** SQLAlchemy 2 models (`fin_persistence.tables`), repository functions, and Alembic migrations that live **inside the `fin_persistence` package** (`migrations/`, shipped in the wheel so non-editable images can migrate). Migrations are hand-written; a test asserts they match `models.py`, so every model change needs a new revision. Code must run on both Postgres (production) and SQLite (fast tests), hence the dialect switch in `repo._insert`. Key semantics:
- `fundamental_facts` keeps every filed version of a fact with its `filed` date; `repo.facts_as_of(as_of)` returns only what was public then (restatements invisible until filed). Instant facts store `period_start == period_end` so the natural key has no NULLs.
- `repo.upsert_securities` only updates columns a row provides (absent columns are left alone, so the universe sync never wipes a resolved CIK).
- TimescaleDB is optional: the migration turns `price_bars` into a hypertable only if the extension exists. The database must be UTF-8 (SQL_ASCII makes psycopg 3 return bytes and breaks SQLAlchemy).

**Metrics layer (`fin_domain.scoring.metrics`, `fin_application.scoring`).** Bridges storage and scoring: `calculate_metrics(security, facts, latest_bar, as_of)` (pure) builds a `SecurityMetrics` using only data public at `as_of` (`known_as_of` over the filed versions, latest price bar <= `as_of`); the use case `ScoreSecurityLive` loads those inputs through the ports, then assesses and decides. `fin_domain.market_data.annual_series` (moved from `metrics/annual.py`) decides which facts count: 10-K family only, flow concepts need a ~1-year duration, stock concepts are balance-sheet instants, and when a concept is reported under several XBRL tags the highest-priority tag in `CONCEPT_TAGS` wins per fiscal year. Each ratio uses numerator and denominator from the same fiscal year (an older value never leaks into a newer ratio; a warning says when a ratio had to use an older year); the book value pairs equity with the share count on the same 10-K's cover. Missing data stays `None` and is explained in `metrics.warnings`, never silently filled, with two documented exceptions that also warn: missing debt is 0 only when that year's balance sheet exists, and no dividend data means 0 dividend years. Non-positive EPS/equity are kept as negative ratios so scorers can reject them explicitly. `signal_blockers` (a subset of the warnings: no or stale price, no or stale fundamentals) makes `decide_signal` withhold buy/sell signals while the score is still reported. Graham's P/E uses `pe_avg3` (3-year average EPS), falling back to latest-year EPS with a note. Multi-class issuers (`MULTI_CLASS_TICKERS`, e.g. BRK-B) get no book value/P/B, because EDGAR's company facts have no class dimension; `normalize_facts` drops same-key facts with conflicting values instead of letting one class overwrite another. `annual_series` also derives `TotalDebt`: the one definition of debt every consumer uses (the noncurrent tag plus the current portion, but never adding the current portion to the total tag, which already includes it), and keeps share counts from a single source per company (cover page before balance sheet) so year-over-year share changes never compare different kinds of count. `SecurityMetrics.annual` carries the fiscal-year history the multi-year scorers use. `score_security` = metrics + engine + `decide_signal`; the API exposes it as `GET /api/securities/{ticker}/score`.

**Signals and alerts (`fin_domain.signals`, `fin_application.{signals,alerts,scoring_run,watchlist}`, `fin_persistence.signals`, `fin_telegram`).** Scoring is a persisted state machine. `ScoreUniverse.record` stores every run in `scores` (append-only; the JSON `details` is the typed `ScoreDetails`, read and written by `fin_persistence.score_codec` in the same shape as always) and feeds the graph a `previous_conviction` taken from the last *actionable* stored score: conviction set AND not computed on blocked (stale/missing) data. A blocked run is stored but never becomes the baseline (otherwise the buy would be swallowed when fresh data arrives); a NULL-conviction run is not a baseline either, so the next real score is `emerging`, not `buy`. Re-running with unchanged data is idempotent. `fin_domain.signals.AlertPolicy` (values from `config/alerts.yml`, loaded by `fin_config.load_alert_policy`) decides which signals become alerts: sells only for watchlist stocks, a 24h per-kind cooldown overridden by a >= 10 point conviction move. **Hysteresis**: after a buy/emerging signal another buy needs conviction to have fallen below 65 (`BUY_REARM_BELOW`) in between, after a sell another sell needs it back at >= 55 (`SELL_REARM_ABOVE`); derived from stored scores by `buy_armed`/`sell_armed` over `ScoreRepository.convictions_since_last_signal` (actionable scores only) and passed to `decide` as `buy_armed`/`sell_armed`, so a score flapping around 70 or 50 signals once. **Delivery** is channel-independent and crash-safe: creating an alert also writes its `alert_deliveries` rows in the same transaction (in_app `sent`; muted channel `skipped`; others `pending`), so a channel enabled later never replays old alerts (no rows exist for it). Sending (`DeliverDueAlerts`) happens after commit, outside any DB transaction: each delivery is first claimed by an atomic compare-and-set on `attempts` (`Delivery.claim` then `AlertRepository.save_delivery(expected_attempts=...)`, which raises `ConcurrencyConflict` for the loser), so concurrent callers (scoring run and worker) cannot double-send; the outcome is recorded in its own short transaction. A failed delivery is retried with backoff (`retry_backoff_minutes`, `max_delivery_attempts`), a `pending` row left by a dead process is retried after `pending_timeout_minutes`, and a channel muted when a delivery falls due has it set to `skipped`. A channel exception never escapes (`ChannelError` text is recorded; any other exception by type only). Signals carry `processed_at`/`suppressed_reason`: `ProcessSignals` decides per signal in its own transaction, and `run_scoring` also sweeps signals left unprocessed by an interrupted run (`SignalRepository.pending_ids`) without re-alerting deliberately suppressed ones. The in-app feed (`GET /api/alerts`) is always on. Telegram (`fin_telegram`: `client.py` is the plain-httpx client and channel, `bot.py` the command bot answering only the configured chat and calling `BotCommands`) exists only when `FEATURE_TELEGRAM_ENABLED` is on: off means no client, no token needed and zero calls; on without `TELEGRAM_BOT_TOKEN`/`TELEGRAM_CHAT_ID` fails at startup (`ChannelConfigError`). The bot token is in every request URL, so it is kept out of errors and logs. Bot polling is at-most-once: the update offset is persisted (`BotCursorStore`, kept in `channel_state.update_cursor`) before each command runs, so a failing reply or a restart never replays `/mute` or `/unwatch`. `RunScoring` (`fin_application/scoring_run.py`) = score universe + alerts + delivery pass, tracked in `ingestion_runs` (source `scoring`; `partial` if any security or `signal <id>` failed, `failed` if every security failed). The worker (`fin_worker`, `python -m fin_worker`) holds a Postgres advisory lock through `PgAdvisoryLeaderLock` (the `SingleInstanceGuard` port, `Container.leader_lock`), which re-verifies the lock every loop (`pg_locks`), re-acquires it after a lost connection and exits with status 3 if another instance took it (status 2 on invalid channel config). `scores` is append-only and not yet pruned; a retention policy is on the backlog.

**Paper-trading sandbox (`fin_domain.sandbox`, `fin_application.sandbox`, `fin_persistence.sandbox`, `config/sandbox.yml`).** The rules are the `Portfolio` aggregate (orders, fills, holdings, strategy, snapshots; money is `Decimal`), which never reads storage: it states the prices it needs (`price_requests`), the application fetches exactly those (`load_price_book`) and hands them back as a `PriceBook`, freshly built before each step. Tables `portfolios`, `sandbox_orders`, `portfolio_snapshots` (migration 0004); Decimal money, fractional shares. A portfolio is `manual` (orders from the API/UI; `PlaceOrder`) or `strategy` (`Portfolio.apply_signals` turns signals created *after the portfolio existed* into orders: buy/emerging spends `position_pct` of total value subject to `max_positions`, `min_cash_pct` and cash already committed to pending buys; sell closes the position and cancels a pending buy; each signal is looked at once via `portfolios.last_signal_id`, and `sandbox_orders.signal_id` keeps the trade linked to its score for later attribution/tuning). **Fill model: an order decided on day D fills at the close of the first stored bar on a later day** (never D's own close), at the source's *adjusted* price; cash and holdings are checked at fill time (reject with a reason). `Portfolio.settle` only uses bars up to its `as_of` and processes orders by fill bar, sells before buys on the same close (a sale can fund a purchase). **Holdings are derived, not stored** (`Portfolio.holdings`, average-cost accounting from the filled orders): each fill is restated to today's share basis by `fill price / current stored close of its bar`, because the price source re-adjusts history after a split or dividend (ingestion re-backfills), so a 2:1 split is neither a loss nor a gain and dividends appear as slightly more shares; buy fees are part of the cost basis. A strategy looks at each signal once: a buy skipped for lack of cash, slots or a price bar is not reconsidered, and cancelling a strategy-created order does not re-place it (both deliberate). `RunSandbox` takes a row lock on each portfolio (`PortfolioRepository.load_exclusive`, `FOR UPDATE` on Postgres) so overlapping runs cannot duplicate orders. Order sizes are bounded and finite-checked; `buy_kinds` may only contain `buy`/`emerging`. `Portfolio.snapshot` produces one value row per portfolio and day (the equity curve; idempotent). `RunSandbox` (flow `sandbox-step`, last step of the daily pipeline, source `sandbox` in `ingestion_runs`) processes each portfolio in its own transaction. API: `/api/portfolios` (+ `/{id}`, `/history`, `/orders`; writes need the token). The API's 422 responses omit the rejected input (a custom `RequestValidationError` handler), because echoing `Infinity`/`NaN` made FastAPI's own error body fail to encode. Not built: benchmark comparison, shorting, limit orders, cash interest.

**Market Data, providers and ingestion (`fin_domain.market_data`, `fin_application.ingestion`, `fin_providers`, `flows/fin_flows/ingestion.py`).** The use cases `SyncUniverse`, `IngestPrices`, `IngestFundamentals`, `IngestYields` (`fin_application/ingestion.py`) depend only on ports (`fin_application.ports.market_data`: `SecurityRepository`, `PriceRepository`, `FactRepository`, `YieldRepository`, and the sources `FundamentalsSource`, `PriceSource`, `YieldSource`, `UniverseSource`), keyed by `Ticker`. The adapters are `fin_providers` (`edgar.py`: ticker->CIK and XBRL company facts; `fred.py`; `yfinance_provider.py`; `alphavantage.py`, a fallback that is not wired; `sources.py` turns vendor shapes into domain `Fact`/`PriceBar`/`YieldPoint`), `fin_persistence.market_data` (SQL repositories over `fin_persistence/repo.py`) and `fin_config.YamlUniverseSource`; `fin_bootstrap.Container` wires them and builds the vendor clients lazily (no SEC contact or FRED key needed by processes that never ingest). The rules are in the domain: concept tags and classifications (`concepts.py`), the point-in-time view (`known_as_of`), fiscal-year series (`annual_series`), restatement detection (`is_restated`), candle aggregation, universe validation. Provider errors must never contain credentials (API keys travel in query strings). Every ingestion use case writes an `ingestion_runs` row (`fin_application.runs.tracked_run` over `JobRunTracker`): a run is `failed` until it completes normally, one bad ticker/series (including DB errors) makes it `partial`, `RateLimitError`/`AccessDeniedError` abort it, and stale `running` rows are failed by the next run. Prefect flows in `flows/` are thin wrappers that raise on a total failure. `fin_flows.pipeline.daily_pipeline_flow` chains sync-universe, prices, yields, fundamentals, scoring and the sandbox step in one flow (a failing step does not stop the later ones; the flow fails at the end naming them), and is the only scheduled deployment (`fin_flows.serve`, weekdays 21:30 UTC); each step is also deployed without a schedule for manual runs. The always-on minute-level loop is meant to be a separate service, not a Prefect job.

**Config and flags.** `config/*.yml` is found by `fin_config.ConfigLocator` (explicit directory, else `FIN_CONFIG_DIR`, else the nearest `config/` above the package; used by `load_config`, `YamlUniverseSource`, `AlertPolicy.load`, `SandboxConfig.load`, `FeatureFlags`), which is why Docker images copy `config/` next to the venv. Feature flags come from `config/features.yml`, overridable by `FEATURE_<NAME>` env vars; `telegram_enabled` is off by default and, when it exists, must not start the bot or require a token while off.

**API and web.** `apps/api` (`fin_api.main`) exposes `/healthz` (liveness), `/readyz` (config/graph load plus a DB check when a DB is configured; 503 if unreachable), `/api/features`, `/api/score` (score caller-supplied metrics; responses include `guardrail_results`) and `/api/alerts` (feed with cursor and unread filter; `POST /api/alerts/{id}/read`), `/api/opportunities` (ignores scores older than `max_age_days`, default 10), `/api/watchlist`, `/api/portfolios` and `/api/channels` (database-backed; 503 without a database), `/api/securities` (search by ticker prefix/name matched literally, sector, kind `stock|etf`; flags the watchlist; inactive securities are not listed but their history is served), `/api/securities/{ticker}/prices` (daily adjusted bars; beyond `max_points` they are merged into candles from the newest bar, keeping true highs/lows and summed volume), `/api/securities/{ticker}/scores` (stored score history with blocked/all-abstained runs flagged, plus the signals inside the returned window as chart markers; plot against `as_of`, not `computed_at`), and `/api/securities/{ticker}/score` (score a stored ticker live; for today without `previous_conviction` the signal is judged against the stored baseline and hysteresis, so it is set only when a transition happened since the last stored score; 404 unknown ticker, 422 future `as_of`, 503 without or with an unreachable database). **Web UI (`apps/web`).** Vite + React 18 + TypeScript, React Router, TanStack Query, `lightweight-charts`, plain CSS (dark). Pages: Opportunities (ranked table, sector filter/sort, watch star), Security detail (score, price candles, conviction history with signal markers, per-philosophy criteria with actual vs limit, data warnings/withheld-signal notice, simulated order ticket), Alerts (feed, unread filter, mark read, cursor paging), Sandbox (portfolio list/create, portfolio page with equity curve, positions, orders, cancel), Settings (flags, channels), plus a search box. `src/api/` has the typed client (`client.ts`, `hooks.ts`); the browser **never holds the write token**: nginx (`deploy/nginx.conf.template`, rendered by envsubst from `API_TOKEN`/`AUTH_BASIC`) adds `Authorization: Bearer` to `/api` requests and prod compose puts the UI behind basic auth (mounted htpasswd, required; `/healthz` is exempt; the container speaks plain HTTP, so a TLS terminator must sit in front). Every state-changing `/api` request must carry `X-Requested-With: fin-app` (the client sends it; nginx answers 403 otherwise), because browsers attach cached basic-auth credentials to cross-site requests and nginx adds the token. `deploy/web-entrypoint.d/10-validate-env.sh` refuses to start with an `API_TOKEN` outside `[A-Za-z0-9._~-]` (it lands in a quoted nginx string; use `openssl rand -hex 32`), an unsafe realm, or basic auth without an htpasswd file; `limit_req` slows password guessing (a speed bump, not a lockout). Dev compose binds its published ports to 127.0.0.1 (auth is off and the token is well known), and `pnpm dev` does the same in the Vite proxy. Charts are mocked in the jsdom tests (no canvas), so chart rendering is only checked by running the app (`scripts/seed_demo.py` + Playwright screenshots); the rendered nginx config (auth, token injection, CSRF header, rate limit, CSP/security headers, fail-closed without htpasswd) is exercised against a real nginx in `flows/tests/test_web_proxy.py` (skipped when nginx/envsubst/openssl are missing: `apt install nginx-light gettext-base`), but the Alpine image build and its entrypoint wiring were not run (no Docker in the sandbox; `scripts/smoke-images.sh` has the checks). Bond screens are not built (no bond scorers).

**API auth.** State-changing endpoints (`PUT`/`DELETE /api/watchlist/{ticker}`, `POST /api/alerts/{id}/read`, `POST /api/portfolios`, `POST`/`DELETE /api/portfolios/{id}/orders`) require `Authorization: Bearer $API_TOKEN` (`require_write_token`, constant-time compare). Default-deny: with `API_TOKEN` unset they return 503; wrong or missing token is 401. Dev compose defaults it to `dev-token`, prod compose requires it. Read endpoints are open: keep the API behind the proxy's auth until the UI has a login.

**Deployment prep.** `deploy/` has one `python.Dockerfile` for all Python images (`--build-arg PACKAGE=fin-api|fin-flows`, must stay `uv sync --no-editable`), a web/nginx image, a dev compose file and a prod-shaped template. A one-shot `migrate` service runs before api/worker/flows. Nothing is deployed anywhere by this repo.

## Constraints and gotchas

- Prefect's server image tag in both compose files must equal the Prefect version locked in `uv.lock` (`flows/tests/test_versions.py` enforces this). `apps/api/pyproject.toml` caps FastAPI below 0.137 because the Prefect version in the shared env breaks on newer FastAPI; re-check both when upgrading Prefect.
- SQLite does not enforce column types/lengths (e.g. `accession` is VARCHAR(32)), so a change to models, repository code or DB-touching tests must also be run against Postgres (`TEST_DATABASE_URL`); that is how a too-long test accession was caught.
- Every `python -m <module>` in the compose files must name a real module (tested).
- Stored prices are the source's split/dividend-**adjusted** prices, not as-traded. If a refresh shows stored bars were restated, `ingest_prices` re-fetches the whole history. A point-in-time backtest of price-based valuation needs raw OHLC plus adjustment factors, which does not exist yet.
- The Telegram channel and bot were written from the Bot API docs and tested only against a mocked API (the sandbox cannot reach Telegram).
- The EDGAR and FRED providers were written from public API docs and tested only against synthetic fixtures (`packages/providers/tests/fixtures`, made-up numbers). They have not been verified against the live APIs (a sandbox that blocks `sec.gov`/FRED cannot run them); the `-m live` tests are the check. The EDGAR 403 rate-limit-vs-bad-User-Agent split is an unverified heuristic. The facts for R&D, inventory, net PP&E and current debt (used by Lynch/Greenblatt/Fisher) only exist after fundamentals are re-ingested; until then those nodes abstain or report "no data". Every concept in `CONCEPT_TAGS` must also be classified as stock, flow or snapshot in `fin_domain/market_data/concepts.py`, or `annual_series` silently drops it (`test_every_mapped_concept_is_classified...` in `packages/domain/tests/test_market_data.py` enforces this).
- All thresholds in `config/philosophies.yml` are reasoned starting points, not calibrated; the planned backtester should tune them. First on the list: Buffett's margin of safety (very strict), then Fisher's R&D criterion, which lowers the score of companies that report no R&D (a deliberate choice, but it biases an equal-weighted composite).
- SEC requires `SEC_USER_AGENT` with contact details; FRED needs `FRED_API_KEY`. Copy `.env.example` to `.env` (never commit it).
